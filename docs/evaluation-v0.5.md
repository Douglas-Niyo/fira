# DRAFT — evaluation protocol v0.5 for author review

Draft following inspection of disclosed development results. No formal evaluation cases have been run. This is a pre-freeze amendment, not an already registered protocol. Record author review and publish the freeze commit before the held-out seed run.

1. Unit and window: one generated government fiscal year, July 2025–June 2026. Deduplicate schemes across all twelve months. A true scheme is in scope if at least one labeled source record is observable by year end. Report observed invoice and payment counts, planted schemes, distinct affected in-period payments divided by in-period payments, and realized prevalence. Prevalence is a simulation parameter, not an estimated fraud rate. Post-period settlements stay in the source data.
2. Design: target about 600/3,000/12,000 invoices by scaling transaction intensity for 60 regular suppliers. This changes density, not staff or procurement structure. Each realistic family uses independent Poisson counts for seven types, with expected counts = target payments × target prevalence / (7 × expected affected payments per scheme). Working sizes per scheme: 1,1,1,1,7.5,2.5,1. Overlap, fiscal cutoffs and randomly generated sizes produce departures; always report realized rates. Keep clean years. Enriched runs plant one of each type; report separately. At high volume a new retired supplier may be required for the inactive-payment injection.
3. Design grid: prevalence 0.1%, 0.5%, 1%; 100/30/30 repetitions per prevalence across the three sizes, plus 30 enriched per size = 570 paired years. Seeds start at 700001 in jobs() order; never use 0,1,2,3,4,7,8,11,42 in the formal grid. Alternate a prespecified stress flag within cells: prefix/suffix reformatting, 12-day split spans, daytime clerk bank changes. Other types keep ordinary variation. These are disclosed stress tests, not concealed challenge cases.
4. Budget: 10 displayed lines per month primary, 5 and 20 sensitivities. A self-approval summary costs one slot. It earns no automatic scheme-detection credit for transactions hidden behind it. For all shared-candidate methods, rank actionable items before summaries. One line per user costs one slot if selected. No reserved slot. Report available and selected summaries: persistent deferral is a governance cost. Unselected summaries remain in the full pack; the benchmark does not certify the control was performed. Opening the supporting detail is included in the separate timed study. Pre-period standing issues first observable at opening enter the first monthly snapshot. Zero months count in the denominator.
5. Candidate universe: B1, B2, B3, B3_min and B4 reorder the same monthly items and summaries. B0 only uses exact-duplicate flagged items and credits those exact records. B1 uses priority then amount; B2 orders actionable items by the six-feature score only; B3 uses priority then the same six-feature score. B3_min keeps the old four-feature model with the new summary policy. B4 is a rules-only diversity comparator: assign each grouped item exactly one family, using the first matching family in this fixed sequence: unsupported (R15), overpayment (R04), bank change (R05), supplier control (R06), duplicate (R01–03), split (R09), approval (R08), supplier record (R10–11). At each slot, choose the least-represented nonempty family; break equal family counts by the best remaining item (tier, amount descending, then ID). Reset counts monthly. This selects the top severity/amount item first and can displace later Tier 1 items. No labels enter this decision. Further ties: amount descending, stable destination identifier ascending. For summaries the amount tiebreak is invoice plus payment activity, not loss. B2 is a ranking ablation on rule-generated candidates, not a standalone transaction detector. No method can improve detection by adding model-only candidates in this experiment.
6. Model features: log(1+payment amount), weekday, same entering/approving user, ACH indicator. B2/B3 additionally use (i) log(1+amount) minus log(1+supplier median amount) and (ii) payment-method rarity, 1−(previous same-method count+1)/(previous payment count+1). Use only prior completed months relative to each row, including training rows. Below three prior supplier payments set both features to zero. The rarity statistic is a descriptive index, not a calibrated probability. These features may describe unusual transfers but cannot establish bank redirection; ordinary-amount duplicates may have no unusual model score. Fit to earlier months only. At least 20 historical payments required; otherwise scores are zero. Isolation Forest: 64 trees, up to 256 observations, fixed seed 117. HBOS: ten equal-width bins per feature, add-one smoothing, clamp outside observations to end bins. Average both empirical score percentiles against training samples. For an item take the maximum score among its primary current payments or current payments applied to its primary invoices by month end; absent scores are zero. No labels, record numbers or transaction identifiers used as numeric features.
7. Outcomes: count a scheme if its primary record occurs in a selected nonsummary item; deduplicate by scheme ID. Do not count blanket context links. Compute FSR with per-type caps min(type count, water-filling level) totaling min(12k, total schemes), equal weights. Normalize each type's found count up to its cap and average. This adapts a transaction-level metric to grouped scheme discovery; one item can credit multiple schemes, so report ordinary scheme recall and type coverage alongside it. Per-year metrics precede averaging. For clean years report load; FSR, recall and type coverage are undefined. Linked planted payment dollars use distinct selected labeled payments only: neither total scheme value nor losses prevented.
8. Primary comparison: B3 minus B1 at k=10 in the 12,000-invoice, 0.5% cell. Evaluate the ranking hypothesis only if at least 25% of its months across all runs exceed the budget. Compare FSR with a 95% paired percentile bootstrap over eligible nonclean years, 2,000 draws, fixed seed 2301; a positive lower bound favors B3. Type coverage is secondary. B4−B1 (queue design), B3−B4 (hybrid versus rules diversity), and B3−B3_min (supplier features at fixed ordering policy) are secondary paired descriptive comparisons; none replaces the primary hypothesis. Inspect tier counts, summary deferral and per-type recall alongside FSR. Other cells, budgets, stress subgroups, type counts and signed-rank tests are descriptive. If pressure is insufficient or the interval includes zero, report that finding; do not select a replacement primary cell.
9. H3: for every nonempty raw alert year, require >=70% fewer top-level lines AND representation of all observable planted schemes in nonsummary items AND traceability from all emitted alerts; retain and report even a single alert with no compression. Zero-alert years have undefined percentage; separately report load, retention failures and count. Line counts do not estimate time. Runtime source-link validation and release regression tests supplement the benchmark’s coverage indicator.
10. Retain all run rows and failed runs; do not reroll a failing seed. Archive the tagged source, exact environment, outputs and deviations. The previous plan’s optional tier-weighted FSR is deferred; no multiple-cell confirmatory claims. Identical-format reviewer materials and independent reproduction are separate evidence. No nonprofit effectiveness or adoption claim follows from this generator.

Freeze sequence: review this exact draft and code, resolve changes, then change the heading to “# FROZEN” followed by date and version, commit the tracked code and protocol, tag that commit FIRA-eval-freeze and publish it before running the held-out grid. Commands are in README. Any subsequent change needs a dated deviation and separate release.

Source for the adapted FSR metric: Gronewald, Scherer and Mehdiyev (2026), Machine Learning for Journal Entry Testing: A Type-Aware Evaluation of Anomaly Detectors under a Review Budget, arXiv:2610.06133, §§3.2, 3.5. The grouped-scheme adaptation and monthly review assumptions are FIRA design choices.

## Pre-freeze change record | 2026-11-24
These changes were motivated by known development outcomes, especially seed 11. No detection windows, generator distributions, labels, candidate-generation rules or disclosed stress variants were changed. The seven-day split rule still faces 12-day spans. New seeds test replication under known patterns, not unseen mechanisms. If a rule is changed in response, retain these cases as regression tests, document the trigger and before/after results, and have an independent reviewer design and privately seal a fresh challenge set before freezing. Record its hash, authorship and unblinding date. No such independently sealed set exists in this release. A null primary result is reportable.
